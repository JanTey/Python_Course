🧹 Шпаргалка: Очистка репозитория GitHub от «мусора»
Этот процесс называется сбросом индекса Git. Он полностью безопасен: файлы удаляются только из памяти Git (и после пуша — с сайта GitHub), но физически остаются целыми и невредимыми на вашем компьютере.

🚀 Полная последовательность команд
Выполняется в Терминале (Terminal) внутри корневой папки вашего проекта:

Bash
# 1. Сбрасываем старую память Git (очищаем кэш отслеживания)
### git rm -r -f --cached .

# 2. Сканируем проект заново с учётом обновлённых правил .gitignore
### git add .

# 3. Записываем изменения в историю (делаем коммит)
### git commit -m "chore: очистка репозитория от системного мусора по .gitignore"

# 4. Отправляем обновлённый порядок на GitHub
### git push
🔍 Разбор команд «по полочкам»
1. git rm -r -f --cached .
   git rm — команда удаления (remove).

-r — рекурсивно (recursive). Проходит по всем вложенным папкам.

-f — принудительно (force). Чтобы Git не останавливался из-за наличия несохранённых изменений.

--cached — самый важный флаг. Удаляет файлы только из индекса Git, не трогая ваши файлы на диске.

. (точка) — текущая директория. Команда говорит: «Забудь всё, что находится в этом проекте».

2. git add .
   Заставляет Git заново просканировать проект. Теперь он сверяется с вашим актуальным файлом .gitignore и добавляет в репозиторий только нужные файлы, игнорируя системный мусор (настройки IDE, кеши, окружение).

3. git commit -m "..."
   Фиксирует изменения. Для Git это выглядит как: «Пользователь убрал лишнее, оставил чистый код и обновил правила игры».

4. git push
   Отправляет состояние на сервер. GitHub получает инструкцию на удаление и мгновенно стирает ненужные файлы из облачного репозитория.
